# 新人第一周指南

欢迎加入云枢科技。这份指南覆盖入职第 1 天到第 7 天该做的事，按顺序做就行，不用一次看完。

## 入职第 1 天：先让工具能用

上午 10:00 前到 3 楼前台报到，HR 会给你工牌、电脑和一份《员工手册》。拿到电脑后按下面顺序配置：

1. 用企业邮箱登录 SSO 门户 `sso.yunshu.internal`，统一改初始密码，**密码必须 12 位以上且包含大小写与符号**。
2. 加入企业微信，扫描 HR 提供的部门群二维码，至少加入「全员群」「你所在部门群」「新人答疑群」三个群。
3. 在 IT 自助平台 `it.yunshu.internal` 提交「开发环境开通」工单，勾选：GitLab、Jenkins、KaiRAG 控制台、数据平台只读权限。一般 2 小时内审批完成。
4. 领取门禁卡并录入指纹，位置在一楼保安室。

第一天不需要写代码，把环境跑通比什么都重要。如果 15:00 前还有工单没批，直接在企业微信找 IT 值班同学（群名「IT 值班」），不要干等。

## 入职第 2—3 天：把项目跑起来

你的导师（Buddy）会给你一个「起手指令」文档，里面写了仓库地址、启动命令和第一个练手任务。标准动作是：

- `git clone` 项目仓库后先读 `README.md` 和 `AGENTS.md`，再动手；
- 本地起服务用 `docker compose up -d`，不要直接在自己机器上装一堆依赖；
- 跑通后**在部门群发一条「环境已就绪 + 截图」**，这是新人融入的第一步，也让导师知道进度。

如果卡住超过 30 分钟，按顺序尝试：先搜内部知识库（KaiRAG 助手），再搜 FAQ 文档，最后才 @ 导师。这不是不让你问，而是让你问得更值。

## 入职第 4—5 天：完成第一个练手任务

第一个任务通常是修一个 P3 小 bug 或补一段文档，目的是走通完整流程：

需求 → 建分支 → 提交 MR → CI 通过 → 代码评审 → 合并 → 预发验证。

任务完成后，在周会上用 3 分钟讲清楚：你改了什么、为什么这么改、遇到什么坑。**讲不清楚说明还没真懂，这是允许的，但要说出来。**

## 入职第 1 周结束时应该达到的状态

| 事项 | 达标标准 |
| --- | --- |
| 账号权限 | SSO、GitLab、Jenkins、KaiRAG 全部可用 |
| 本地环境 | 能独立 `docker compose up` 起服务并访问首页 |
| 流程认知 | 知道 MR 怎么提、CI 红了看哪里、找谁审批 |
| 人际关系 | 认识导师、直属主管、部门内 5 位以上同事 |
| 知识获取 | 会用 KaiRAG 助手提问，知道知识库在哪个入口 |

没达标的项不用慌，第一周的目标是「不迷路」，不是「能打仗」。第二周开始会有正式的任务分配。

## 第一个月要避开的三个坑

1. **闷头做三天不吭声**：进度落后被发现时已经来不及。每天在下班前给导师发一句进度，10 个字也行。
2. **不问就自己猜业务规则**：制度类问题（报销、权限、合规）一定要查知识库或问 HR，猜错成本很高。
3. **把测试环境当生产环境**：所有带 `prod` 字样的地址，操作前必须找导师确认。
