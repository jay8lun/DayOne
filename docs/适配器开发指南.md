# 知识库适配器开发指南

> 目标：**换公司、换知识库平台，不改 RAG 主流程**，只替换/新增一个「适配器」。

---

## 0. 先判断：你需要写代码吗？

```text
你的知识库有 HTTP 接口，能返回 JSON 吗？
├─ 有 → 接口有「文档列表 + 文档详情」（或列表里就带正文）吗？
│        ├─ 有 → 用内置 http_json 适配器 + 写 JSON 配置（0 行代码）★ 90% 的情况
│        └─ 没有（比如要先 GraphQL 查询、要签名、要拼多接口）→ 写代码适配器
└─ 没有（只有 PDF 压缩包 / 共享盘）→ 用 local_dir 适配器（把文件同步到目录即可）
```

三种方式的成本对比：

| 方式 | 代码量 | 适用 |
| --- | --- | --- |
| `local_dir` | 0 | 文档能落到磁盘（md/txt/html/pdf/docx），最省事 |
| `http_json` | 0（只改 `.env`） | 标准 REST 接口，字段名/分页可配置 |
| 自定义 Adapter | 30~80 行 | 私有协议、需要签名、多接口拼装、增量接口特殊 |

## 1. 零代码：http_json 适配器

### 1.1 它假设的接口形状

```text
GET {base_url}{list_path}?{cursor_param}=...&{limit_param}=50
    → {"data": {"items": [ {..}, {..} ], "next_cursor": "..."}}

GET {base_url}{detail_path}       # detail_path 里用 {id} 占位
    → {"data": {"doc_id": "...", "name": "...", "content": {"markdown": "..."}}}
```

只要你的接口能映射成这个形状（绝大多数知识库都能），就不用写代码。

### 1.2 完整配置（写到 `.env` 的 `KB_ADAPTER_CONFIG`）

```json
{
  "base_url": "https://kb.corp.example.com/api/v1",
  "list_path": "/documents",
  "detail_path": "/documents/{id}",

  "auth": {"type": "bearer", "token": "YOUR_TOKEN"},

  "items_path": "data.items",
  "next_cursor_path": "data.next_cursor",
  "cursor_param": "cursor",
  "limit_param": "page_size",

  "fields": {
    "id": "doc_id",
    "title": "name",
    "content": "content.markdown",
    "url": "web_url",
    "updated_at": "updated_at",
    "author": "creator.name",
    "space": "space.name"
  },

  "content_format": "auto",
  "timeout": 20
}
```

同时把 `KB_SOURCE=http_json`。

### 1.3 每个字段的作用

| 配置 | 必填 | 说明 |
| --- | --- | --- |
| `base_url` | ✅ | 接口根地址，末尾不要带 `/` |
| `list_path` | | 目录接口路径，默认 `/documents` |
| `detail_path` | | 详情路径，支持 `{id}` 占位。**不填**则直接用列表里返回的字段当正文 |
| `auth.type` | | `bearer` / `header` / `basic` / `none` |
| `auth.token` / `name`+`value` / `username`+`password` | | 配合上面的类型 |
| `headers` | | 额外请求头，如 `{"X-Tenant": "yunshu"}` |
| `items_path` | ✅ | 列表数组在响应里的位置，支持 `a.b.c` 和数组下标 `a.0.b` |
| `next_cursor_path` | | 下一页游标位置；**不填表示只有一页**（不会死循环） |
| `cursor_param` / `limit_param` | | 分页参数名，默认 `cursor` / `limit` |
| `fields.*` | | 字段映射，`id` 必填，其余缺省有默认值 |
| `fields.content` | | 可以是字符串字段，也可以是 `blocks` 数组（会自动拼接 `text`/`content`） |
| `content_format` | | `auto`（检测到 HTML 标签就转纯文本）/ `markdown` / `html` / `text` |
| `detail_wrap` | | 详情响应外层包名，默认 `data` |

### 1.4 常见接口形态对照

| 你的接口返回 | 配置怎么写 |
| --- | --- |
| `{"items": [...]}` | `items_path: "items"`，去掉 `detail_wrap` |
| `{"code":0,"data":{"list":[...]}}` | `items_path: "data.list"` |
| 列表里就带正文，没有详情接口 | 不填 `detail_path` |
| 分页用页码而非游标 | `cursor_param: "page"`，`next_cursor_path` 指向 `data.next_page`（返回 null 即结束） |
| 时间是毫秒时间戳 | 不用管，`_parse_dt` 会自动识别秒/毫秒 |
| 正文是富文本 HTML | `content_format: "html"` |
| 一个文档分成多个 block 数组 | `fields.content` 指向 `blocks`，会自动拼接 |

### 1.5 用本地 mock 服务先把配置跑通

不用等公司接口，5 分钟就能验证配置对不对。新建 `mock_kb.py`：

     "updated_at": "2026-10-01T10:00:00Z"},
    {"doc_id": "2", "name": "考勤制度", "content": {"markdown": "## 考勤\n9:30 上班。"},
     "updated_at": "2026-10-02T10:00:00Z"},

@app.get("/api/v1/documents")

    return {"data": {"items": DOCS, "next_cursor": None}}

## 2. 写代码：自定义适配器

### 2.1 模板（复制即可用）

```python
# my_company/adapters/confluence.py
from datetime import datetime

from app.adapters.base import (
    DocumentPage, DocumentRef, KnowledgeSourceAdapter, SourceDocument,
)


class ConfluenceAdapter(KnowledgeSourceAdapter):
    name = "confluence"                 # 配置里用 KB_SOURCE=confluence
    description = "Confluence 知识库适配器"
    supports_incremental = True         # 是否支持「只拉变更」
    supports_pagination = True

    def __init__(self, config: dict | None = None) -> None:
        super().__init__(config)
        self.base = self.config["base_url"].rstrip("/")
        self.token = self.config["token"]

    # ---------- 必须实现 3 个方法 ----------
    async def health_check(self) -> bool:
        try:
            page = await self.list_documents(limit=1)
            return True if page.items is not None else False
        except Exception:
            return False          # 不要抛异常，让主流程能降级

    async def list_documents(self, cursor=None, limit=100) -> DocumentPage:
        # 换成你的接口调用
        raw = await self._get(f"/wiki/api/v2/pages?limit={limit}&cursor={cursor or ''}")
        items = [
            DocumentRef(
                external_id=str(x["id"]),
                title=x["title"],
                updated_at=datetime.fromisoformat(x["version"]["createdAt"].replace("Z", "+00:00")),
            )
            for x in raw["results"]
        ]
        return DocumentPage(items=items, next_cursor=raw.get("_links", {}).get("next"))

    async def fetch_document(self, external_id: str) -> SourceDocument:
        raw = await self._get(f"/wiki/api/v2/pages/{external_id}?body-format=storage")
        return SourceDocument(
            external_id=external_id,
            title=raw["title"],
            content=raw["body"]["storage"]["value"],   # HTML 也可以，下游不用管
            url=f"https://wiki.corp.example.com/pages/{external_id}",
            space=raw.get("spaceId"),
            metadata={"source": self.name},
        )

    async def _get(self, path: str) -> dict:
        import httpx
        async with httpx.AsyncClient(timeout=20) as client:
            resp = await client.get(self.base + path,
                                    headers={"Authorization": f"Bearer {self.token}"})
            resp.raise_for_status()
            return resp.json()


# 供插件加载器识别
ADAPTER = ConfluenceAdapter
```

### 2.2 注册方式（三选一）

**A. 插件模块（推荐，不用改本项目代码）**

```bash
# .env
ADAPTER_PLUGINS=my_company.adapters.confluence
```

被 import 的模块里只要有 `ADAPTER = XxxAdapter` 或 `def register(reg): reg(XxxAdapter)`，
启动时就会自动注册（`app/adapters/registry.py::load_plugins`）。
**插件可以放在本项目之外**，换公司时把插件目录拷过去、改一行环境变量就行。

**B. 直接 import 注册**

```python
from app.adapters.registry import register_adapter
from my_company.adapters.confluence import ConfluenceAdapter
register_adapter(ConfluenceAdapter)
```

**C. 在 `app/adapters/__init__.py` 里加一行**（不推荐，会污染主流程）

### 2.3 实现要点（血泪清单）

| 坑 | 正确做法 |
| --- | --- |
| `health_check` 抛异常把服务拖崩 | 捕获所有异常，返回 `False`；主流程会跳过该源继续启动 |
| 分页没有终止条件，死循环 | `next_cursor` 为空/false 就返回 `None`，不要返回 `""` |
| `external_id` 用了标题 | 用平台文档 id。标题一改，`doc_id` 就变，历史引用全断 |
| 正文是 HTML 直接入库 | 交给下游也行（`chunk` 会当纯文本切），但更好的是在适配器里 `_html_to_text` 转一遍，检索更干净 |
| 一次拉全量几千篇 | `fetch_all(limit=...)` 要支持 limit，先 `--limit 5` 验证再全量 |
| 时间格式乱七八糟 | 用 `app/adapters/http_json.py::_parse_dt`，已兼容 ISO / 秒 / 毫秒 / `YYYY-MM-DD` |
| 接口有 QPS 限制 | 在适配器里加 `asyncio.sleep`，或在 `fetch_all` 里批量拉 |
| 正文为空 | 直接 `continue` 或抛错都行，`pipeline` 会记进 `report.errors` 但不中断 |

### 2.4 增量同步（可选但建议）

```python
async def fetch_all(self, limit=None, updated_since=None):
    async for doc in super().fetch_all(limit=limit, updated_since=updated_since):
        yield doc
```

基类默认实现会按 `updated_since` 过滤目录项。若你的接口支持 `?updated_after=`，
直接覆写 `list_documents` 带上参数更省流量。

> 即使不实现增量也没关系：`IngestionPipeline` 会用**内容 SHA1** 做二次过滤，
> 没变的文档不会重新 embedding（省 token）。

## 3. 多源同时挂载

公司的知识库往往不止一个（制度在 Wiki、SOP 在企微、FAQ 在另一个系统）。
`KB_ADAPTER_CONFIG` 支持 JSON 数组：

```json
[
  {"source": "http_json", "base_url": "https://kb.corp/api", "list_path": "/docs",
   "detail_path": "/docs/{id}", "fields": {"id": "id", "title": "title", "content": "body"}},
  {"source": "local_dir", "path": "data/corpus"}
]
```

每个源独立健康检查，**一个挂了不影响其他源**。
入库后 `chunk.metadata.source` 会记录来源，前端/接口可以按源过滤。

## 5. 企业微信文档适配器（现状说明）

`app/adapters/wecom.py` 目前是**占位实现**：注册了、能在 `/api/kb/adapters` 里看到，
但调用会抛 `AdapterNotConfigured` 并给出明确提示。原因是公司尚未开通企微文档接口权限。

接口下来后要动的就 4 个点（文件里已写好 TODO）：

1. `GET /cgi-bin/gettoken?corpid=&corpsecret=` 换 `access_token`（缓存 7200s）；
2. `list_documents` → `GET /cgi-bin/wedoc/get_doc_list`，映射 `docid` / `title` / `update_time`；
3. `fetch_document` → `GET /cgi-bin/wedoc/get_doc_content` 取正文；
4. 把 `docid` 作为 `external_id`，其余塞 `metadata`。

**切块、检索、生成、前端全都不用改**——这就是适配器模式的意义。
